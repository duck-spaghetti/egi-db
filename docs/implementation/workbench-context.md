# Workbench source and interpreted context

Migration 034 refines the frozen request builder without changing existing
extraction v1/v2 or the queue ledger. `preview_analysis_plan` accepts null
configuration to resolve the currently enabled immutable configuration. Existing
bounded plan readers expose only its safe model, price reference and configured
limits, never arbitrary provider configuration or credentials.

An operator-selected original category label can have manual field origin while
remaining an immutable quoted source fact. The builder validates its registered
fact identity, selected input, exact public quote/span and protected-field policy;
it uses original `source_value` regardless of a corrected current `value`.
Manual or cleared name/description edits are excluded from source input. Public
source metadata supplies weaker contextual supports, not independent required
classification bases. Source text and metadata quotes remain separately tagged.

Only explicitly materialized active v3 interpreted classifications enter category
comparison. A contextual unit is `interpretation:<stable UUID>` and its label is
the original full description/basis text, not a placeholder or a selected candidate
name. It references original owned public support and a description basis; it does
not manufacture a literal source fact. Existing matching description bases and
source support keys are reused. Original source keys remain
`support:<record UUID>:<evidence UUID>`, metadata supports have a separate prefix.

All available current supplied catalog alternatives are retained as prior
classification proposals. Omitted unavailable alternatives disclose
`incomplete_catalog`; no supplied candidate is invented. Private candidate-reason
prose is replaced by a fixed server explanation. Raw full input and unrelated
private notes are never sent. A description-only record without materialized
interpretations remains visibly awaiting materialization for grouping; record
classification and comparison progress remain distinct.

Different interpretation identities retain separate occurrence units even when
their descriptions match. Shared label inventory coalesces `(label, context_key)`
frequencies, so two `Mensa` interpretation units produce one inventory entry with
count two. Deterministic equivalence applies only to literal category-label bases;
interpreted descriptions retain their explicit review boundary.

Packing and packet freeze require twice the canonical request UTF-8 byte size
plus 33,792 conservative framing tokens to fit the frozen input ceiling. This
covers user data potentially repeated inside instructions plus the bounded schema
and framing. Long interpretations and oversized dependency/comparison scopes fail
with explicit decomposition codes; no text or alternative is silently truncated.
The approved source/structure packing, output bounds and immutable plan manifests
remain in force. These limits authorize work but introduce no second reservation.

Native contract 39 checks the real manual-origin raw-label path, null configuration,
metadata-only contextual supports, explicit materialization, separate interpretation
units with aggregated inventory, safe prior prose and no-dispatch previews. It uses
synthetic sources and a maintained adopted taxonomy; no real provider is involved.
